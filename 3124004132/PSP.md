# PSP 记录

## 开发前思考

我准备使用 Python 3 完成本次作业。选择 Python 的原因是中文文本处理、单元测试和性能分析工具比较方便，同时不需要额外发布可执行文件。

这次作业不仅要得到一个重复率，还要求记录完整的软件开发过程。我希望把输入输出、相似度计算、异常处理和测试拆开完成，避免最后一次性写完后难以定位问题。

下面的预计时间在正式编码前填写。实际耗时是在程序完成后结合开发过程回顾的有效工作时间，不把中间休息和等待时间算进去。

## 回头看这次估时

总时间只比预估少了 15 分钟，看起来估得挺准，但每一项其实差得不少。设计文档比预计快，因为程序规模不大，三个模块的职责很快就能确定；真正花时间的是编码和测试。第一版余弦相似度对增删文本给出的分数太高，后来增加覆盖率、三元特征，又重新跑样例和回归测试，这部分一开始没有估够。

测试也不是最后一次写完的。文件读写、规范化和相似度每完成一部分，我就跟着补对应测试，最后再集中检查分支覆盖率。这样比最后一次性补测试多花了一点时间，但出了问题更容易知道是哪一层。

这次统计的 3 个程序文件共 275 行，3 个测试文件共 557 行，不包含 Markdown 文档、虚拟环境和自动生成的覆盖率报告。测试代码比程序本身还多，主要是异常输入和边界分支比较多。下次预估时，我会把“拿真实样例调整算法”和“覆盖率补漏”单独列出来，而不是都塞进编码和测试两个大项里。
