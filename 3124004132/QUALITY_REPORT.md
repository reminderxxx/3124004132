# 测试与代码质量记录

## 这次检查了什么

程序目前有文件读写、文本规范化、特征提取、重复率计算和命令行入口几个部分。我用 `unittest` 跑全部测试，用 `coverage` 看语句和分支覆盖率，再用 `ruff` 检查比较常见的代码问题。

检查环境：

- Python 3.9.6
- coverage 7.10.7
- ruff 0.16.7

正式检查命令：

```bash
python -m unittest discover -s tests -v
coverage run -m unittest discover -s tests
coverage report -m
coverage html
ruff check .
```

## 覆盖率结果

目前共有 71 个测试。最终覆盖率如下：

| 文件 | 语句数 | 未覆盖语句 | 分支数 | 未完整覆盖分支 | 覆盖率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `file_utils.py` | 28 | 0 | 14 | 0 | 100% |
| `main.py` | 26 | 0 | 4 | 0 | 100% |
| `plagiarism_checker.py` | 92 | 0 | 32 | 0 | 100% |
| **合计** | **146** | **0** | **50** | **0** | **100%** |

第一次统计时其实只有 99%，缺的是 `main.py` 最后真正启动程序的那一行。这个入口已经在子进程测试里实际运行过，只是子进程的数据没有自动算进当前覆盖率文件。我给它加了明确的覆盖率排除注释，没有为了把数字刷到 100% 再写一个重复测试。

HTML 报告生成在 `htmlcov/index.html`。`htmlcov/` 只属于本地自动生成的检查结果，不提交到 GitHub。

## Ruff 检查过程

第一次跑 Ruff 时出现了 6 条提示，其中 3 条是 import 排版问题，另外 3 条建议把类型标注换成 Python 3.10 才支持的 `X | Y` 写法。

作业没有规定必须使用很新的 Python，我现在的环境是 Python 3.9，所以没有为了消除提示就把代码改成不兼容的语法。我在 `pyproject.toml` 里明确设置 Python 3.9，再整理了 3 处 import。重新检查后结果为：

```text
All checks passed!
```

这次修正只调整了 import 附近的空行，没有改查重算法。

## 我现在怎么看这个 100%

71 个测试和 100% 覆盖率至少说明主要分支都实际走过，像文件不存在、空文本、非法特征、错误参数和防止覆盖原文这些情况不是只写在说明里。

不过覆盖率高不等于算法一定准。它只能说明代码被测试执行过，不能证明重复率符合所有论文的真实情况。算法准确度还要结合不同增删改文本继续看，性能部分也要单独做分析，不能拿这个 100% 代替后面的工作。

目前还没有在 Windows 10 上实际运行，也没有专门模拟操作系统拒绝文件写入的场景。这两项先作为环境相关风险保留。
